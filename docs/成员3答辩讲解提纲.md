# 成员3答辩讲解提纲

建议控制在 3–5 分钟，并在系统演示过程中穿插说明，不要只念技术名词。

## 开场（约20秒）

> 我负责后端服务、数据库和权限设计。我的核心目标是保证前端每个操作都有真实持久化和服务端校验，尤其是 AI 结果不能直接成为正式任务，必须经过人工确认。

## 1. 架构与数据库（约50秒）

> 前端 React 只调用 `/api`；Node 后端处理认证、权限、业务规则和模型调用；数据保存在 SQLite。数据库把 AI 草稿 `task_drafts` 和正式任务 `tasks` 分开，每次调用记录在 `extraction_runs`，人工修改记录在 `audit_logs`。因此可以追溯一条任务来自哪次会议、哪次提取、被谁修改和确认。

展示：数据库 ER 图或迁移 SQL，重点指四张表 `meetings → extraction_runs → task_drafts → tasks`。

## 2. AI 安全边界（约50秒）

> 后端把会议日期、团队成员名单和纪要原文一起交给模型，并要求返回 JSON。模型结果回来后还会二次校验：负责人必须是团队成员，日期必须合法，原文依据必须能在纪要中逐字找到。不明确的信息保留为空并标记待确认。例如“大家周五讨论”不会自动绑定某个同学。

展示：AI 草稿页的“待人工核对”原因，以及修正前后的负责人。

## 3. 权限与事务（约50秒）

> 权限不只靠前端隐藏按钮。后端会验证 token、团队、角色、资源归属和可修改字段。组长可以确认草稿和管理任务；组员只能修改自己任务的状态和进度；教师/助教只读。草稿确认使用数据库事务，同时完成创建任务、锁定草稿和记录日志，任何一步失败都会全部回滚。

展示：用组员账号打开他人任务是只读，或展示自动化测试中 403 用例。

## 4. 统计与逾期（约35秒）

> 数据库不保存“已逾期”这种会随日期变化的状态。接口每次根据截止日期和基础状态动态判断，所以跨过截止日后无需人工更新或定时任务，统计会自动正确。完成率、成员负载和状态分布也全部从正式任务实时聚合。

展示：组员把自己的任务改为已完成，统计页完成率随之变化。

## 5. 安全与测试（约45秒）

> 密码使用随机盐的 scrypt 哈希；随机登录 token 在数据库中也只保存哈希。AI Key 只存在后端 `.env`，不会进入浏览器。自动化测试覆盖日期解析、完整提取确认流程、三类角色、越权字段、跨团队隔离、动态逾期、审计记录和语音转写接口，目前 15 项自动化测试全部通过。

展示：终端运行 `npm run test:backend` 的结果。

## 收尾（约15秒）

> 这部分工作的价值是把 AI 的不确定输出变成了可验证、可追溯、受权限保护的业务流程；即使 AI 识别错误，也不会未经人工确认就影响团队任务。

## 可能被问到的问题

### 为什么用 SQLite？

课程小组并发量低，SQLite 无需单独部署数据库，便于演示和交付；同时使用标准关系模型、外键、索引和事务，将来迁移到 MySQL/PostgreSQL 时结构可以保留。

### 为什么 AI Key 不能放前端？

浏览器源码和请求对用户可见，任何打包进前端的密钥都等于公开。后端代理调用可以保护密钥并统一控制调用次数、校验输出和保存记录。

### 如果模型输出的 JSON 格式错了怎么办？

后端拒绝这次结果，把 `extraction_runs` 标记为失败并返回 502，不写入半成品草稿；用户可修正纪要或重新提取。

### 为什么不把“已逾期”存进任务状态？

逾期由时间推导，今天未逾期的任务明天可能逾期。存储它会过时并要求定时同步；动态计算能保持单一事实来源。

### 如何证明组员不能越权？

自动化测试不用页面，直接拿组员 token 调用修改他人任务和修改标题的接口，后端分别返回 403，说明安全不是靠按钮隐藏。

### 如何分析 AI 效果？

`extraction_runs` 保存输入快照、模型和提示词版本，`task_drafts` 保存原始结构，`audit_logs` 保存人工修改字段。可以计算负责人修正率、日期修正率、直接确认率和提示词版本间差异。
