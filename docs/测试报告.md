## 前端验证状态

已完成的静态检查：

- `src/api/api.js` 已无 Mock 数据和业务 `localStorage`；仅在本地保存会话 token、当前公开用户和最近提取会议 ID；
- 所有业务页面改为请求真实 REST API；
- AI 页面可保存修正、确认和拒绝草稿；
- 任务页面更新使用基础状态 `statusCode`，不允许人工选择“已逾期”；
- 教师只读提示和控件禁用已接入；
- 会议页已接入麦克风录音、停止、试听、清除、文件选择、上传状态和转写结果回填；
- 上传使用 `FormData`，浏览器自动生成 multipart boundary，不再错误强制 JSON Content-Type；
- React/Vite 依赖已固定版本，避免 `latest` 带来的不可重复构建。

当前打包工作区未携带 `node_modules`，因此此处执行 `npm run build` 会提示 `vite: not found`。这不是源码构建错误；交付包仍保持依赖固定且不包含体积巨大的依赖目录。解压后先安装依赖，再构建：

```bash
npm install
npm run build
```

若构建成功，再进行下面的浏览器验收。

## 浏览器手工验收脚本

1. 用组长账号登录，在会议页允许麦克风权限；
2. 录制几秒语音，停止并试听，点击“转写并填入纪要”；
3. 在 `mock` 模式确认示例文字被填入；在 `api` 模式确认实际语音文本被填入；
4. 新建会议，核对纪要后点击 AI 提取；
5. 确认前两条有成员和日期，第三条负责人待确认；
6. 把第三条负责人改为张三，保存并确认；
7. 在团队看板找到新任务；
8. 退出并使用组员账号登录，更新自己的任务并确认他人任务只读；
9. 打开统计页，确认图表变化；
10. 使用教师账号确认录音、保存和编辑控件不可用；
11. 再用组长查看系统记录，确认转写、修改和确认日志存在。

## 回归测试要求

修改数据库结构、权限、草稿确认逻辑、状态规则或统计 SQL 后，都必须重新运行后端测试；修改 React 页面或 API 封装后，还必须重新执行前端构建和完整浏览器验收。
