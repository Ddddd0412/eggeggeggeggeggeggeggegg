## 前端验证状态

已完成的静态检查：

- `src/api/api.js` 已无 Mock 数据和业务 `localStorage`；仅在本地保存会话 token、当前公开用户和最近提取会议 ID；
- 所有业务页面改为请求真实 REST API；
- AI 页面可保存修正、确认和拒绝草稿；
- 任务页面更新使用基础状态 `statusCode`，不允许人工选择“已逾期”；
- 教师只读提示和控件禁用已接入；
- 会议页可上传录音，转写由后端调用并回填纪要；
- React/Vite 依赖已固定版本，避免 `latest` 带来的不可重复构建。

当前已在 Codex Node.js 运行时执行生产构建并通过。交付前仍可在团队电脑上复验：

```bash
npm install
npm run build
```

若构建成功，再进行下面的浏览器验收。

## 浏览器手工验收脚本

1. 用组长账号登录；
2. 新建会议，输入示例纪要并点击 AI 提取；
3. 确认前两条有成员和日期，第三条负责人待确认；
4. 把第三条负责人改为张三，保存并确认；
5. 在团队看板找到新任务；
6. 退出并使用组员账号登录；
7. 尝试打开他人任务，应只读；更新自己的任务状态；
8. 打开统计页，确认图表变化；
9. 使用教师账号登录，确认新增/编辑入口不可用；
10. 再用组长查看 `/api/audit-logs` 或测试工具，确认修改和确认日志存在。

## 回归测试要求

修改数据库结构、权限、草稿确认逻辑、状态规则或统计 SQL 后，都必须重新运行后端测试；修改 React 页面或 API 封装后，还必须重新执行前端构建和完整浏览器验收。
