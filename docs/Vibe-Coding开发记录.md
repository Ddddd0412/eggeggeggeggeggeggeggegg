# 成员3 Vibe Coding 开发记录

以下记录覆盖成员3后端与数据库工作。每条都包含目标、给 GPT 的具体需求、AI 结果、遇到的问题、人工验证与修改、最终结果，可直接作为课程开发过程材料，再补充你自己的截图和日期。

## 记录1：数据库实体拆分与迁移

**本次目标**

把“用户、团队、会议、AI 草稿、正式任务、状态记录”转成可实现的关系数据库，避免 AI 数据和正式业务数据混在一起。

**给 GPT 的具体需求**

> 根据会议纪要转任务系统需求设计 SQLite 表。AI 输出必须先成为草稿，组长确认后才生成正式任务；需要三类角色、提取记录、人工修改记录、软删除和统计查询。请说明主键、外键、枚举、唯一约束和索引。

**AI 生成结果**

初步给出 `users`、`teams`、`team_members`、`meetings`、`extraction_runs`、`task_drafts`、`tasks`、`audit_logs`、`auth_sessions` 九张表，并建议为团队/状态、负责人/状态、团队/截止日期建立联合索引。

**遇到的问题**

最初方案考虑直接把 AI 结果写进 `tasks`，这样无法区分“模型建议”和“已经确认”，也无法阻止重复确认。

**我的验证和修改**

我按核心流程逐步检查每次数据状态，决定把草稿和正式任务分表；给 `tasks.source_draft_id` 加唯一约束；在 `task_drafts` 保存原始负责人、相对日期、歧义原因和原始 JSON；用迁移脚本实际创建数据库并检查外键。

**最终结果**

形成 `server/migrations/001_initial.sql` 和数据库设计文档，能够追踪“纪要 → 提取运行 → 草稿 → 正式任务”的完整来源。

## 记录2：登录认证与角色权限

**本次目标**

实现安全登录、团队隔离和组员/组长/教师三类权限，保证权限不只停留在页面按钮层。

**给 GPT 的具体需求**

> 使用 Node.js 原生模块实现密码存储和 Bearer Token 会话。密码不能明文；组长管理全部任务，组员只能修改自己的状态和进度，教师/助教只读；每个接口还要校验 team_id，给出可测试的 401/403 规则。

**AI 生成结果**

生成 `scrypt` 密码哈希、随机 token、token 哈希入库、过期时间校验，以及 `authenticate`、`requireTeamAccess`、`requireLeader`、`requireStudentWrite` 等中间逻辑。

**遇到的问题**

前端原型使用 `localStorage` 保存包含明文密码的 Mock 用户，而且组员权限主要靠隐藏按钮，直接调用接口仍可能越权。

**我的验证和修改**

我移除了 Mock 用户数据，检查登录响应不包含 `password_hash`，直接查询数据库确认保存值以 `scrypt$` 开头；用组员 token 尝试修改他人任务和标题，确认后端分别返回 403；用教师 token 尝试新增会议，同样返回 403。

**最终结果**

认证和三类角色权限在服务端生效，前端提示只是辅助；跨团队查询也由后端 `team_id` 条件隔离。

## 记录3：AI 提取、日期解析与防编造校验

**本次目标**

实现“会议纪要 → JSON 草稿”，并确保模型不虚构负责人、日期或原文依据。

**给 GPT 的具体需求**

> 编写一个结构化任务提示词和服务端校验器。模型必须输出任务名称、负责人、原始日期表达、绝对日期、优先级、原文引用和歧义原因。负责人只能来自团队成员，“下周三”以会议日期计算，“大家”不能自动分给某人，引用必须存在于原文。

**AI 生成结果**

生成版本化提示词、OpenAI-compatible API 调用、JSON 解析、成员精确匹配、日期归一化、原文子串校验，以及无需外部密钥的本地确定性演示模式。

**遇到的问题**

第一次测试中，“下周三前”被正则只截取成“周三前”，导致 2026-09-08 的任务被算成 09-09，而不是 09-16。

**我的验证和修改**

我增加固定会议日期的单元测试，打印实际草稿定位到正则分组错误；把“下周/本周/周”改为完整互斥模式后重新测试，确认“下周三=09-16、周五=09-11”。同时保留“月底前”返回空值，不让系统猜测。

**最终结果**

示例纪要稳定生成三条草稿；“大家”显示待确认；相对日期可复现；无效 JSON、陌生成员、无效日期和虚构引用都会被后端拦截或标记。

## 记录4：人工确认、任务更新与事务

**本次目标**

保证 AI 草稿只有经过组长确认才能进入看板，并确保确认操作不会产生半完成数据。

**给 GPT 的具体需求**

> 设计草稿修改、拒绝和确认接口。确认必须在 SQLite 事务中创建正式任务、把草稿改为已确认、记录审计日志；负责人或截止日期不明确时返回 422；同一草稿不能重复确认。

**AI 生成结果**

生成 `PATCH/DELETE /api/ai/drafts/:id`、`POST /api/tasks/confirm` 和任务 CRUD，使用 `source_draft_id UNIQUE` 防重复，并记录字段级修改日志。

**遇到的问题**

前端保存修改时同时传了旧 `assigneeId` 和新负责人姓名，后端如果优先读 ID，会忽略用户刚选择的新负责人。

**我的验证和修改**

我把接口规则改为显式传入负责人姓名时优先按姓名重新映射，并让前端只提交可编辑字段；又补充原文依据编辑与二次子串校验。测试未完整草稿返回 422，修正后才允许确认。

**最终结果**

确认链路具备完整性、幂等约束和审计证据，页面修改的负责人能够正确写入正式任务。

## 记录5：动态逾期、统计和审计记录

**本次目标**

实现完成率、逾期、成员负载和状态分布，确保第二天打开系统仍显示正确结果。

**给 GPT 的具体需求**

> 设计统计 SQL。“已逾期”不能依赖人工更新，应由今天日期、截止日期和基础状态动态判断；统计要排除软删除和已取消任务，并按成员返回总数、完成数和逾期数。

**AI 生成结果**

生成 SQLite 条件聚合查询和任务序列化规则：数据库只保存待开始/进行中/已完成/已取消，API 额外返回 `status`、`statusCode` 和 `isOverdue`。

**遇到的问题**

原前端允许用户在下拉框中直接选择“已逾期”，这会导致状态与截止日期矛盾，并可能影响统计真实性。

**我的验证和修改**

我删除了前端“已逾期”更新选项，保留其作为筛选和看板列；后端收到手工设置“已逾期”时返回 `DERIVED_STATUS`。我修改一项任务为已完成后重新请求统计，确认进度自动变成 100、完成数同步增加。

**最终结果**

任务状态和统计数据由同一套规则生成，不会因前端缓存或人工设置产生不一致；修改前后值可在审计日志中查看。

## 记录6：前后端联调与自动化测试

**本次目标**

把原来基于 `localStorage` 的前端演示替换为真实 REST API，并用自动化测试验证完整链路。

**给 GPT 的具体需求**

> 保持现有 React 页面样式，重写 `src/api/api.js` 接真实后端；修复“点击提取时重复保存会议”的问题；草稿页从服务器加载，任务页使用服务端动态状态。用 Node 内置测试框架覆盖登录、提取、修正、确认、权限、统计、审计和团队隔离。

**AI 生成结果**

前端统一通过带 token 的 `request` 函数访问 `/api`；会议先保存或更新再提交 `meetingId`；草稿和任务刷新后仍从 SQLite 读取。生成端到端 API 自动化测试。

**遇到的问题**

早期执行环境无法从 npm registry 下载 React/Vite 依赖；录音功能加入后，还需要确保音频只上传后端、API 密钥不暴露给浏览器，并为转写失败提供明确提示。

**我的验证和修改**

我完成依赖安装并执行 `npm test`，结果为 15 项测试通过、0 项失败；执行 `npm run build` 后，Vite 成功构建 52 个模块。随后又在真实浏览器中按“登录—创建会议—AI提取—修正负责人—确认—看板—统计”的顺序完成端到端验证。

**最终结果**

后端核心流程、越权场景和语音转写接口已经自动验证，前端生产构建与浏览器闭环均通过；项目提供统一启动、迁移、测试和构建命令，并附完整接口、权限与部署文档。
