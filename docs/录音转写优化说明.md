# 录音转写优化说明

本次优化补齐了“前端能录音，但后端没有真实上传与转写接口”的缺口。完整链路为：

```mermaid
flowchart LR
    A[录音或选择文件] --> B[试听]
    B --> C[上传并转写]
    C --> D[人工核对文字]
    D --> E[保存会议]
    E --> F[AI提取任务]
```

## Windows 上更新后怎么运行

把新压缩包解压到一个新目录，在该目录打开 PowerShell：

```powershell
Copy-Item .env.example .env
npm install
npm run db:setup
```

开发模式需要两个终端：

```powershell
# 终端1
npm run server
```

```powershell
# 终端2
npm run dev
```

打开 `http://localhost:5173`。不要在开发模式中直接打开 `http://localhost:3001/login`；3001 是后端地址，只有执行 `npm run build` 后才会同时提供生产前端。

## 先用离线模式验收

`.env` 保持：

```dotenv
TRANSCRIPTION_MODE=mock
```

使用组长或组员账号登录，进入“会议纪要”：

1. 点击“开始录音”，浏览器询问时允许麦克风；
2. 说几秒后点击“停止录音”；
3. 点击播放按钮试听；
4. 点击“转写并填入纪要”；
5. Mock 模式会填入固定示例文字，证明录音、上传、接口、数据库和回填链路正常；
6. 填写标题并保存，再点击“AI提取任务”。

也可以点击“选择音频文件”上传已有录音。支持 mp3、wav、m4a、ogg、flac、mp4、webm，最大 25 MiB。

## 切换真实语音转写

在 `.env` 中配置：

```dotenv
TRANSCRIPTION_MODE=api
TRANSCRIPTION_API_URL=https://api.openai.com/v1/audio/transcriptions
TRANSCRIPTION_API_KEY=你的服务端密钥
TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe
TRANSCRIPTION_LANGUAGE=zh
TRANSCRIPTION_TIMEOUT_MS=60000
TRANSCRIPTION_MAX_BYTES=26214400
```

保存后按 `Ctrl+C` 停止后端，再执行 `npm run server` 重启。密钥只写在 `.env`，不要写进 React 源码、`VITE_*` 变量、截图或提交记录。

## 常见报错

| 现象 | 处理方法 |
|---|---|
| 麦克风被拒绝 | 点击地址栏左侧权限图标，允许麦克风并刷新 |
| `ERR_CONNECTION_REFUSED` | 检查对应终端是否仍在运行；开发页面是 5173，后端是 3001 |
| `EADDRINUSE: 3001` | 已有一个后端在运行，不要重复启动；关闭旧终端或结束旧 Node 进程 |
| 413 | 音频超过 25 MiB，截短或压缩 |
| 415 | 改用支持的音频格式 |
| 502/503/504 | 检查真实接口地址、密钥、模型和网络；先切回 Mock 定位问题 |

## 安全与数据说明

- 接口先验证登录和角色，再读取音频；教师/助教不能上传或转写；
- 原始音频不保存到 SQLite；
- `transcription_runs` 只保存文件元数据、状态、转写文字和安全错误；
- 每次成功或失败都会写入审计日志；
- 浏览器永远拿不到后端转写密钥。
